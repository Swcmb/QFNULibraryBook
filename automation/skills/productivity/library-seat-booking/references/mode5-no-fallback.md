# MODE=5 无降级行为记录

## 现象

MODE=5（直连 POST）对指定座位**不做任何降级**。座位不可用时，脚本会一直重试直到 max_attempts（默认 300 次）。

## 时间消耗

- 每次尝试间隔约 3.5 秒（含重试）
- 300 次 × 3.5s ≈ **17.5 分钟**
- 期间 CPU/网络资源持续占用，日志文件持续增长

## 与 MODE=4 的区别

| 模式 | 抢到座位 | 座位被占 | 超时行为 |
|------|---------|---------|---------|
| MODE=4 | 直接返回成功 | 60 次后自动降级为随机抢（SEAT_FALLBACK_AFTER=60） | 降级后仍有机会 |
| MODE=5 | 直接返回成功 | **一直重试到 300 次**，绝不换座位 | 0 收获退出，失败 |

## 建议

1. **热门座位不要用 MODE=5**：252、226 这类热门座极易被他人约走，MODE=5 无退路
2. **改用 MODE=4**：有 SEAT_FALLBACK_AFTER 降级机制，60 次抢不到会自动随机抢
3. **如果必须用 MODE=5**：设置环境变量降低重试次数：
   ```bash
   MAX_ATTEMPTS=30 bash book-seat.sh  # 缩短等待时间
   ```
4. **监控日志大小**：300 次重试会产生大量日志，必要时监控 `/tmp/seat-*.log`

## 相关配置

- `SEAT_FALLBACK_AFTER`：仅对 MODE=4 生效，控制降级阈值
- `MAX_ATTEMPTS`：MODE=5 的总重试次数上限（默认 300）
